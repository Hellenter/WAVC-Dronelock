# Несколько широких камер

Установка: две-три широкие камеры смотрят каждая на свой сектор, точная камера на поворотке — одна на
всех. Цель, которую видит любая широкая, — цель установки с одним номером: когда её видят две камеры
сразу (перекрытие секторов) или она перелетает из сектора в сектор (в том числе через щель, где её не видит
никто), номер не меняется, и точная её не бросает.

Код: `native/include/dronolok/multicam.hpp` (объединение целей, калибровка), `netmsg.hpp` (сообщения по
сети, сверка часов, UDP), C API `dl_fusion_*`, `dl_msg_*` в `dronolok.h`, Python — `Fusion`,
`encode_targets`, `decode_targets` в `native/python/dronolok_native.py`.

## Как работает

- **Система отсчёта — поворотка точной.** Каждая широкая шлёт свои цели в своей системе (направление по
  паспорту установки: куда смотрит ось, где стоит), объединение переводит их в систему поворотки: поправка
  калибровки и параллакс, если камера стоит не у поворотки (`pos`, м; дальность цели неизвестна, поэтому
  неуверенность направления растёт с параллаксом).
- **Сопоставление.** Сообщение камеры связывается с целью установки, у которой прогноз ближе допуска:
  `gateDeg` + `gateSigma` · СКО прогноза и сообщения + размер цели. Трек камеры, связанный с целью,
  остаётся с ней, пока приходит. Новый трек у края сектора, куда по прогнозу летит цель другой камеры, —
  та же цель.
- **Щель между секторами.** Цель, которую не видит ни одна камера, ждёт по прогнозу `coastS` секунд (4 с):
  неуверенность прогноза растёт со временем, и цель находит соседняя камера. Камере, к которой цель летит,
  приходит подсказка (`cues`): в этом месте порог детектора ниже — цель берётся с первых кадров.
- **Две камеры видят одну цель.** Сообщения о ней — от той камеры, где цель дальше от края кадра
  (переход с запасом `edgeDeg`, без дребезга). Две цели, совпадающие `mergeS` секунд, — одна (младший
  номер остаётся). Класс и жёсткий захват держатся `keepS` секунд после перехода.
- **Калибровка широких по точной.** Пока точная ведёт цель и уверена, что это дрон, её направление
  сравнивается с направлением по каждой широкой, которая видит цель: так оценивается малый поворот
  камеры относительно паспорта (МНК по парам, старые пары забываются). Неуверенность калибровки входит в
  СКО сообщений — окно поиска точной шире, пока калибровка не сошлась. Проверка «точная ведёт не то, что
  широкая» считает эту неуверенность сдвигом, а не шумом: допуск на неё `--check-bias` (3) её СКО, а не 6,
  как на шум сообщения, — иначе при 0.5° допуск 3° и точная сидит на помехе рядом с целью. А сползание точной
  с цели видно и до калибровки: смещение точной от прогноза широкой в первые 0.15 с захвата — это сдвиг
  калибровки, дальше, пока точная не подтвердила дрон, смещение сверяется с ним с обычным допуском (0.5°).
  Калибровку можно сохранить (`saveCalib`) и загрузить при следующем запуске.
- **Одна широкая** — без изменений: номера целей = номера треков камеры, сообщения без пересчёта.

## Варианты установки

**Одно устройство на все широкие** (например, Raspberry Pi 5 с двумя камерами CSI): кадры в такт,
конвейер на каждую камеру, объединение там же; поворотке уходит одно сообщение с целями установки.
Нагрузка — сумма камер: на эмуляторе 8–11 мс на кадр 16 Мп на камеру (ПК, Xeon 2.3 ГГц, 4 потока); Pi 5
по оценке медленнее в ~2.8 раза — ~25 мс на камеру, две — ~50 мс из 71 мс при 14 к/с. Укладываются, но
без большого запаса (оценка, на устройстве — замерить `dronolok_bench --calibrate`); не хватит —
профиль «Экономия» или 12 Мп.

**Устройство на камеру** (Pi на камеру): каждая камера шлёт свои цели устройству поворотки по UDP, раз в
кадр, одна датаграмма; объединяет устройство поворотки. Потеря датаграммы не страшна: следующее сообщение
через 1/14 с несёт всё заново. Часы устройств сверяются как в NTP (запрос — ответ, смещение по самому
быстрому обмену из последних 16), время кадра в сообщении переводится в часы поворотки. Подсказки
(`DLC1`) и «это птица» (`DLB1`) идут обратно камерам.

```
DLW1 cam seq t sent n;id az el vaz vel sigma sigma_v cls hard size conf;...   цели камеры (её система, её часы)
DLC1 cam t n;az el r;...       подсказка камере: где ждать цель, градусы
DLB1 cam local                 трек камеры — птица (точная рассмотрела)
DLP1 seq t1                    сверка часов: запрос
DLQ1 seq t1 t2 t3              ответ
```

Строка с 18 целями — ~1.3 КБ (в датаграмму без фрагментации), на деле ~6 КБ/с на две камеры.

## Из Python (Pi)

```python
from dronolok_native import Camera, Target, Fusion, encode_targets, decode_targets
cam = Camera(4608, 2592, 120)
f = Fusion()                                     # на устройстве поворотки (или на устройстве с камерами)
f.add_camera(cam, (0, 30, 0))                    # ось по паспорту: азимут, угол места, поворот кадра
f.add_camera(cam, (110, 30, 0), pos=(0.4, 0, 0)) # вторая: на 0.4 м восточнее поворотки
f.load_calib("calib.txt")

# камера k по кадру t: её треки -> цели (Target.from_track), по сети — encode_targets / decode_targets
f.update(k, t, targets)
for g in f.targets():          # цели установки: g["id"], g["target"] (система поворотки), g["cam"], g["seen_by"]
    ...
f.observe_reference(gid, narrow_target, confident=True)   # точная ведёт цель gid: калибровка широких
det_k.set_focus(f.cues(k, t))                             # подсказка камере k
```

## Эмулятор

Вкладка «Две камеры» → «Широкие камеры»: число широких (1–3), угол между осями (меньше поля зрения —
перекрытие, больше — щель), где работают (одно устройство / устройство на камеру: задержка и разброс сети,
ошибка часов, сверка часов, настоящий UDP), объединение целей, калибровка, подсказка соседней камере,
ошибка установки, доля целей, летящих через стык. «Поворот широкой камеры» — у выбранной камеры (кнопки
и стрелки). Справа — переходы целей между камерами с тем же номером и с новым, время, когда у одной цели
два номера, калибровка каждой камеры (неуверенность и правда).

Без окна:

```sh
dronolok_app --twocam --wides 2 --wide-step 110 --seam 1 --drones 3 --seconds 60      # перекрытие 10°
dronolok_app --twocam --wides 2 --wide-step 135 --seam 1 --seconds 60                # щель 15°
dronolok_app --twocam --wides 2 --deploy net --udp --clock-err 0.05 --seconds 60     # устройство на камеру
dronolok_app --twocam --wides 2 --install-err 0.5 --seconds 60                       # ошибка установки 0.5°
dronolok_app --twocam --wides 2 --no-fusion ...                                      # для сравнения: без объединения
```

Ещё: `--wide-az 0,110` (оси по списку), `--cam-pos N:x,y,z` (м), `--cam-err N:аз,у.м.,поворот`,
`--net-latency`, `--net-jitter`, `--phase` (кадры камер не в такт), `--no-clock-sync`, `--no-calib`,
`--calib-init`, `--check-bias`, `--no-cross-cue`. 3D-сцена Godot рисует вторую и следующие широкие своими камерами
(`--scene ... --wides 2`).
