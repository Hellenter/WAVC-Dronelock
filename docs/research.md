# Опыт других: детекция малых целей и что из этого взять в Дронолок

Задача близка к трём направлениям: соревнование **Drone-vs-Bird** (видимый диапазон, дроны и птицы на дальних
дистанциях), **Anti-UAV** (ИК и видимый, трекинг малых БПЛА) и классическая **детекция точечных целей в ИК**
(ракеты, самолёты на фоне неба и облаков). Ниже — что там работает и насколько это подходит под Raspberry Pi.

## Что делают другие

**Drone-vs-Bird (WOSDETC, 2017–2024).** Почти все лучшие решения — нейросетевые детекторы (YOLO, Faster R-CNN)
на кадрах с увеличенным разрешением или по тайлам, плюс временная информация: разность соседних кадров или
стопка из 3–5 кадров на вход сети, затем трекер. Главные трудности, которые называют организаторы: цели
меньше 10–20 пикс., птицы, облака и деревья, кадры высокого разрешения. Вывод для нас: нейросеть на весь
кадр 16 Мп для Pi слишком дорога, но её место — второй шаг на вырезках вокруг уже найденных треков
(дрон/птица/помеха), именно там соревнования дают больше всего выигрыша.

**Anti-UAV (CVPR-воркшопы 2020–2025, CST Anti-UAV).** Бенчмарки ИК-трекинга крошечных БПЛА. Лучшие методы —
сиамские/трансформерные трекеры с пространственно-временным вниманием и повторным поиском цели после потери.
Для нас полезна идея повторного захвата: после потери искать цель сначала у прогноза, затем расширяющимся
окном (у нас уже есть), и держать "шаблон" цели (вырезку) для сверки при перезахвате.

**ИК-детекция точечных целей (классика, дёшево).**
- *Морфологический top-hat* и его варианты — то, что у нас уже есть (закрытие линиями в 4 направлениях).
- *LCM / MPCM / RLCM / TLLCM* — локальная контрастная мера "центр против 8 соседних ячеек", многомасштабная.
  По сути то же, что наш top-hat + тайловый отбор; выигрыш у них — проверка, что цель контрастна
  **со всех сторон** (не край облака). Наши 4 направления закрытия это уже делают.
- *CFAR-порог* (порог = k x локальный шум) — стандарт для радаров и ИК. **Сделано в этом PR** (`auto_thr`).
- *TCF, временная фильтрация пикселя* (Temporal Contrast Filter, временной профиль пикселя): при неподвижной
  камере цель — короткий "провал" во временном ряду пикселя, облако — медленное изменение. Дёшево (один
  буфер фона), но цель должна смещаться медленнее размера пикселя за кадр.
- *Track-before-detect (TBD)*: динамическое программирование (Barniv, Tonissen & Evans), фильтр частиц,
  преобразование Хафа по стопке кадров. Энергия цели копится вдоль возможной траектории за N кадров, поэтому
  видны цели с SNR 2–3, которые одиночным кадром не отделить от шума. Полный DP-TBD дорог (перебор скоростей),
  упрощённый вариант — последовательное подтверждение трека по сумме правдоподобий. **Упрощённый вариант
  сделан в этом PR** (`ev_confirm`).
- *Нейросети для ИК малых целей* (DNANet, ISNet, UIU-Net и др.) — точнее классики на сложном фоне, но для
  16 Мп на Pi неподъёмны; годятся на ROI или на NPU.

## Что из этого уже есть в Дронолоке

Морфологический отклик по 4 направлениям, тайловый отбор с отсевом текстуры (аналог LCM), маска неба и зоны,
многомасштабность, карта и долгая память статичных помех, трекер на Калмане с удержанием захвата,
классификатор дрон/птица по ритму взмахов (PR #3).

## Слабые места, найденные на синтетике

Сгенерировал ролики с тусклыми дронами (контраст 6–14 вместо 25–50) и разным шумом матрицы (`synth_sky.py
--drone-contrast 6,14 --noise 1|2|3`):

1. **Постоянный порог `thr = 10` подобран под шум ~2 уровня.** При шуме 3 — 98 ложных треков на кадр, а маска
   неба при обучении считает всё небо "текстурой". При шуме 1 тусклые дроны теряются, хотя видны глазом.
2. **Подтверждение "3 попадания из 5" пропускает шум у порога.** Если снизить порог, ложные треки растут
   лавинообразно (thr 5 — 23 на кадр).
3. **Один кандидат на тайл** (64x64 пикс. кадра): дрон рядом с более контрастной точкой в том же тайле
   не виден.
4. **Облака, дрейфующие с постоянной скоростью**, дают долгие "медленные" треки (на синтетике ~0.6 пикс./кадр —
   ровно скорость облаков).

## Рекомендации на следующие шаги (по соотношению польза / нагрузка)

1. **Включить порог по шуму по умолчанию в приложении** и проверить на реальных роликах со стационарной
   камеры (утро, день, вечер). Нужна галочка в приложении — передал треду приложения.
2. **Накопление отклика по времени (DP-TBD на грубой сетке).** Хранить карту отклика, уменьшенную max-пулингом
   до ячеек 8x8 пикс., и на каждом кадре: `A = 0.7 * dilate3x3(A) + R`. Цель, летящая до ~8 пикс./кадр,
   копит энергию, шум — нет. Ожидаю видимость целей с контрастом в 1.5–2 раза ниже. Цена — один проход по
   карте 0.25 Мп на кадр (~0.2 мс на Pi 5). Для неподвижной камеры это самый сильный следующий шаг.
3. **Два кандидата на тайл** (второй максимум вне окрестности первого) — дрон рядом с бликом или другой
   целью. Цена — второй проход только по "интересным" тайлам.
4. **Отсев треков, летящих вместе с облаками.** Оценить общий дрейф облаков (медиана скоростей медленных
   треков или GlobalMotion по облачной текстуре) и не выдавать трек, чья скорость совпадает с ним и контраст
   у порога.
5. **Временная разность для неподвижной камеры (TCF-подобно)**: фон = медленное среднее уменьшенного кадра;
   цель на текстуре (на фоне веток, облаков) видна в разности, хотя тайл "текстурный". Добавлять только в
   смешанных зонах, чтобы не платить за всё небо.
6. **NPU / нейросеть на вырезках 32x32 вокруг треков** (Hailo-8L на Pi 5): дрон / птица / помеха — по опыту
   Drone-vs-Bird именно это даёт главный прирост в различении. Нужен набор вырезок с реальной камеры —
   приложение может их сохранять.
7. **Реальные данные.** Синтетика не моделирует сжатие камеры, атмосферное дрожание и настоящие облака.
   Короткие ролики со стационарной камеры (даже без дрона — для оценки ложных) дадут больше, чем любая
   настройка на синтетике.
