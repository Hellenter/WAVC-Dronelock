# Дронолок: быстрая детекция точечных целей на 16 Мп

Прототип детектора дронов для широкоугольной (120°) камеры 4608x3456.
Python + OpenCV + NumPy, только CPU (GPU не нужен, но есть флаг `--umat` для OpenCL).

## Результат (4608x3456, 4 ядра CPU облачной машины)

| Вариант | мс/кадр | FPS |
|---|---:|---:|
| Наивный «темнее/светлее всех 8 соседей» (NumPy, векторно) | 354 | 2.8 |
| Морфология, полный размер, 4 потока | 129 | 7.7 |
| Морфология + пулинг 2x2, 1 поток | 56 | 17.8 |
| **Морфология + пулинг 2x2, 4 потока** | **21** | **~48** |

Время включает детекцию тёмных и ярких целей и трекинг; декодирование видео
не входит (кадры заранее в памяти, как будет с сырым потоком камеры).

Качество на синтетическом ролике (облака, кромка леса, провода, 4 дрона 1.5–4 px,
один подсвечен = яркий, 3 ласточки), 3 прохода по 100 кадров:

- найдено дронов: 95.5% кадров (пропуски в основном в первых кадрах трека, нужно 3 попадания из 5);
- ласточки: 97% (как и договаривались, считаются целями);
- ложных подтверждённых треков: 1.2 на кадр с авто-маской леса, 6 на кадр без неё.
  Оставшиеся ложные почти все на проводах.

## Как это работает

1. **Пулинг 2x2 без потери точек.** Для тёмных целей берём минимум из 2x2, для ярких максимум.
   1-пиксельный дрон не исчезает (в отличие от обычного уменьшения), а работы в 4 раза меньше.
2. **«Окружена со всех сторон»** — та же идея, что в текущем алгоритме, но через морфологию.
   Закрытие (closing) линейным ядром 7 px «заливает» тёмные детали короче 7 px вдоль
   своего направления. Минимум закрытий по 4 направлениям (—, |, \, /) минус кадр = насколько
   точка темнее окружения во всех направлениях. Провод и край облака хотя бы в одном
   направлении дают ~0 и отсеиваются. Для ярких целей то же самое с открытием (opening).
   Каждая операция — O(1) на пиксель с SIMD, вместо 8+ сравнений на пиксель в Python/C-цикле.
3. **Поиск максимумов по тайлам 32x32** (dilate + выборка), без сканирования всех пикселей.
   Тайл отбрасывается, если в нём много откликов (листва, рябь облаков): дрон — изолированная точка.
4. **Авто-маска** (`--learn-mask N`): камера стоит на месте, поэтому тайлы, которые постоянно
   «текстурные» (лес, земля), исключаются по первым N кадрам.
5. **Трекер + карта статичного клаттера.** Цель подтверждается после 3 попаданий из 5 кадров.
   Места, где детекции повторяются каждый кадр (углы проводов, просветы в листве), гасятся.
   Скорость трека сохраняется, по ней потом можно отличать ласточек (резкие, быстрые).
6. **Параллель по полосам кадра**: кадр режется на горизонтальные полосы с перекрытием,
   полосы считаются в потоках (OpenCV отпускает GIL). Масштабируется по ядрам почти линейно.

## Запуск

```bash
pip install -r requirements.txt

# синтетический 16 Мп ролик с разметкой (≈7 мин на генерацию 100 кадров)
python synth_sky.py --out data/sky16mp.mp4 --frames 100

# зацикленный прогон: окно на экране + запись демо + метрики
python run_demo.py data/sky16mp.mp4 --loops 3 --learn-mask 25 --show --out demo.mp4

# своё видео (например, ролик с YouTube), растянутое до 16 Мп
python run_demo.py my_drone.mp4 --upscale 4608x3456 --learn-mask 25 --show

# таблица скоростей
python bench.py data/sky16mp.mp4
```

Основные параметры `PointDetector`: `thr` (минимальный контраст, уровни яркости), `k` (максимальный
размер цели после пулинга), `pool` (1 или 2), `workers` (число полос и потоков), `max_density`
(насколько «текстурным» может быть тайл).

## Ограничения и что дальше

- Реальных роликов с дронами в этой среде скачать не удалось (YouTube и датасеты закрыты),
  поэтому проверено на синтетике. Следующий шаг: прогнать на настоящем видео с вашей камеры
  или с YouTube (Drone-vs-Bird, Anti-UAV) через `--upscale`.
- Зависший дрон (почти неподвижный секунду и больше) карта клаттера со временем погасит.
  Он не теряется совсем, а помечается серым; если это критично, клаттер надо учить только
  по треку без движения или по заранее снятой маске.
- Цели крупнее ~14 px (в 16 Мп) не ловятся при `k=7, pool=2`: это уже близкий дрон, его видно
  и без этого детектора. Можно добавить ещё уровень пирамиды.
- На машине с большим числом ядер или с OpenCL GPU (`--umat`) запас по скорости ещё больше.
