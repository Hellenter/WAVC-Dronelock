# Дронолок — тестовое приложение

Проигрывает видео через нативный детектор и трекер, рисует, что алгоритм считает дроном, птицей, шумом и
помехой, и показывает скорость. Ресурсы для алгоритма можно урезать, чтобы примерно повторить
Raspberry Pi или другое железо.

## Запуск (Windows 10/11 x64)

Распакуйте архив и запустите `Dronolok.exe`. Установка и DLL не нужны, всё внутри.
Откройте видео кнопкой «Открыть видео…» или перетащите файл в окно (mp4, mkv, avi, mov, ts, y4m;
кодеки H.264, H.265, VP8/9, MJPEG, MPEG-4).

Если рядом с видео лежит разметка `<имя видео>.gt.json` (её пишет `detector/synth_sky.py`), приложение
рисует её зелёным и считает полноту и долю верно названных классов. Тестовое видео 16 Мп с разметкой
лежит в артефакте `sample-video` сборки GitHub Actions.

## Что на экране

Главное всегда на виду и крупно. **Слева сверху:** «Открыть видео», «Устройство» (этот ПК или имитация
Raspberry Pi 5/4/3), «Профиль алгоритма» (Полный / Баланс / Эконом / Минимум) и «Держать темп камеры».
Под ними вкладки: **Видео** (подача кадров, скорость, источник, повтор), **Железо** (скорость устройства,
потоки, SIMD, ядра, потолок CPU, разрешение), **Алгоритм** (блоки профиля), **Тонко** (пороги, трекер,
птица/дрон, кнопка «Вернуть по умолчанию»), **Вид** (что рисовать на кадре), **Разметка**.
**Справа сверху** — плитки: к/с обработки, доля пропущенных кадров (зелёный — успевает за камерой,
жёлтый/красный — нет), время детектора, загрузка CPU и крупный статус захвата. Под ними вкладки **Время**,
**Цели**, **Качество** (по разметке и сохранение отчётов), **Система**. **Снизу** — крупные кнопки плеера,
скорость x0.1–x1 и шкала. У большинства настроек есть подсказка «(?)».

Подробно по разделам:

- **Слева — управление.**
  - *Подача кадров:* «как камера» отдаёт кадры с частотой видео (или заданной); если алгоритм не успевает,
    лишние кадры выбрасываются, как на реальной камере. «Максимально быстро» показывает предел скорости.
    «Предзагрузка в память» убирает декодирование из замера (декодер H.264 16 Мп сам по себе тяжёлый).
  - *Ресурсы:* число потоков детектора, набор инструкций (AVX2 / SSE2 / скалярный), какие ядра CPU доступны
    процессу, закрепление потоков за ядрами, потоки декодера, жёсткий потолок загрузки CPU в процентах
    (Windows Job Object), приоритет, разрешение обработки и «мин. мс на кадр».
  - *Устройство:* Raspberry Pi 5, 4, 3 или своё. Ставит 4 ядра, векторы 128 бит (как NEON) и растягивает
    обработку каждого кадра во столько раз, во сколько ядро устройства медленнее ядра ПК. Скорость ПК
    меряется при запуске (эталонный замер, мс на 1 Мп), скорость Pi — оценка: точное число даёт
    `dronolok_bench --calibrate` на самом устройстве, его можно ввести в поле «мс/Мп на устройстве».
    Вместе с устройством ставится подходящий профиль алгоритма.
  - *Блоки алгоритма (под железо):* профиль — Полный (каждый кадр целиком, 3 масштаба), Сбалансированный
    (по умолчанию), Экономный (Pi 4–5: весь кадр через кадр, 2 масштаба), Минимальный (Pi 3: только точки и
    тёмные цели, кадр вдвое меньше, весь кадр раз в 3). Ниже — сами блоки, каждый можно переключить:
    масштабы, учёт движения камеры, зоны кадра, тёмные/яркие цели, маска неба, память помех, экономия.
    «Держать темп камеры» — авто-упрощение: если кадр обрабатывается дольше, чем приходит следующий,
    алгоритм упрощается ступенями (реже крупные масштабы, реже весь кадр, меньше масштабов) и возвращается,
    когда запас появился. Ступень видна в метриках и в CSV (`gov_level`). Пример: v2 (720x1280, 30 к/с) при
    имитации Pi 3 (x13): без подстройки пропущено 32% кадров и захват 83% кадров, с авто-упрощением — 6% и
    99%, с профилем «Минимальный» — 1.4% и 99%.
  - *Видео:* пауза, кадр назад / вперёд, скорость x0.05–x2 (замедление — в режиме «как камера»), ползунок
    истории на паузе. Назад листаются уже обработанные кадры с разметкой (последние 600 кадров, не больше
    1 ГБ); вперёд с последнего кадра — обработка следующего.
    Клавиши: **пробел** — пауза, **← / →** — кадр назад / вперёд, **+ / −** — быстрее / медленнее.
    «Пропускать повторы кадра»: запись экрана 60 к/с с ролика 25–30 к/с повторяет каждый кадр 2–3 раза;
    с галочкой повтор не обрабатывается (трекер видит ролик с настоящей частотой, как с камеры 25–30 к/с),
    без неё — обрабатывается как новый кадр. По умолчанию выключено: на записях экрана так захват в
    среднем держится лучше.
    «Чистый старт (без накопленного опыта)»: память статичных помех (`.static.bin`) и маска неба
    (`.mask.bin`), накопленные прошлыми запусками рядом с видео, не загружаются и не перезаписываются, а
    на каждом проходе зацикленного видео маска неба учится заново — видео проверяется так, будто открыто
    впервые. Включение забывает уже накопленное и начинает видео сначала. Мультитест всегда идёт так
    (кроме `--mask-file`).
  - *Разметка целей:* своя разметка роликов, чтобы приложение считало полноту и ложные цели, а шкала
    показывала, где дрон пропущен. Включите «размечать на видео», поставьте паузу и щёлкните по дрону:
    на этом кадре появится опорная точка (рядом с целью алгоритма она прилипает к ней). Между точками
    положение считается по прямой — точку достаточно ставить раз в 10–30 кадров и на поворотах; объект
    есть от первой до последней точки. Правый щелчок — убрать точку. «+ дрон» / «+ птица» — ещё объект.
    «Вести точки по цели» (включено): щелчок по дрону (или кнопка «вести точки по захвату») — и дальше,
    пока видео идёт, точки ставятся сами раз в N кадров: по треку алгоритма, а где трека нет (трекер
    сбросил треки, медленный дрон принят за помеху, захват перешёл на новый номер) — по картинке, по виду
    дрона около прошлого места. Дрон не нашёлся больше секунды — видео встаёт на паузу, щёлкните по нему
    снова. Ушло на другой объект — пауза, стрелкой влево назад к ошибке и щелчок по дрону: точки пойдут
    заново от этого кадра (и с кадра из истории), старые на пройденном участке заменятся. На wt15 один
    щелчок на кадре 362 провёл дрон до конца ролика (кадр 807), расхождение с ручной разметкой до 9 пикс.
    «Переходы»: «< точка» / «точка >» (PageUp/PageDown) — к соседней опорной точке выбранного объекта;
    «< спорное» / «спорное >» (Ctrl+PageUp/PageDown) — к месту, где алгоритм и разметка расходятся: захват
    дольше ¼ с не на метке, захват есть, а метки на кадре нет (разметка кончилась раньше дрона), или метка
    между точками прыгнула намного дальше обычного (точки уехали на другое пятно). Ищется по уже
    просмотренным кадрам; на шкале — оранжевые метки сверху. Не всё спорное — ошибка разметки: часто это
    алгоритм захватил кромку деревьев. На wt17 так нашлись кадры 159–378, где метка ушла с дрона.
    «В ролике нет дронов» — для пустых роликов: любая цель и любой захват на нём считаются ложными.
    Сохраняется сразу в `<видео>.gt.json` (тот же формат, что у `synth_sky.py`, плюс опорные точки), его
    читает и `dronolok_bench --gt`.
  - *Алгоритм:* порог контраста или «порог по шуму» (считается на каждом кадре от шума неба, текущие шум и порог видны в метриках), размер цели, полярность; «размер цели» (сколько масштабов: 1 — только точки,
    до 4 — близкий дрон до ~110 пикс.), «движение камеры» (съёмка с рук), «искать возле прогноза»
    (эксперимент). «Авто» для кадра до 2 Мп включает 3 масштаба и учёт камеры, для 8–16 Мп — нет.
    Трекер: радиус поиска, манёвренность цели, сколько кадров держать цель на прогнозе, порог смены
    захвата, пороги классификатора дрон/птица.
    «Крупная цель целиком (силуэт)»: у крупного БПЛА детектор находит части (крыло, хвост, подвес);
    вокруг захваченной цели ищется её силуэт — связная тёмная (светлая) область, — и захват держится за
    центр всей цели, а части не становятся отдельными целями. Прицел рисуется по габариту силуэта.
    «Жёсткий захват дрона» (вкладка «Тонко»): захваченная цель проверяется — N кадров подряд дрон по
    классификатору и уже пролетела по сцене (по умолчанию 25). После этого на кадре и в статусе
    «ЗАХВАЧЕН ДРОН»: захват не переходит на другие цели, держится на прогнозе дольше (60 кадров), детектор
    смотрит вокруг дрона, а весь кадр — раз в 6 кадров. Пока идёт проверка, у прицела «дрон? 12/25».
    Снимается, если цель оказалась надписью поверх кадра или уверенно птицей. Всё это настраивается и
    выключается. «На мачте или столбе — не дрон»: если от захваченной цели вверх или вниз тянется длинная
    тонкая линия (мачта прожектора, столб, ствол), захват снимается и цель становится помехой.
    «Ожидание размера»: видимый размер захваченной цели и скорость его изменения (приближается /
    удаляется) видны в статусе захвата; по ним выбирается масштаб поиска вокруг цели, а силуэт, внезапно
    ставший намного больше ожидаемого, не принимается.
    «Камера ведёт цель» (вкладка «Алгоритм»): «виртуальная поворотка» — проверка захвата для камеры на
    поворотном устройстве. Алгоритм видит не весь кадр, а окно (по умолчанию половина ширины и высоты), и
    окно, как камера на подвесе, поворачивается за захваченной целью: цель стоит почти в центре, фон едет
    навстречу. На экране — то, что видит такая камера, в строке над видео — где окно в кадре. По
    умолчанию окно поворачивается только за проверенным дроном (жёсткий захват); пока его нет, стоит, а
    без цели 120 кадров возвращается в центр. Настраиваются поле зрения, резкость и предел поворота.
    Надписи поверх записи экрана (логотипы, «Идёт запись», кнопки плеера) распознаются по тому, что стоят
    на месте кадра, когда камера движется, и не захватываются; захват, ставший помехой, отпускается сразу.
    «Память статичных помех» (неподвижная камера): места, где цели появляются и никуда не летят
    (катушки ЛЭП, фонари), запоминаются и показываются крестиками; память лежит рядом с видео
    (`<видео>.static.bin`), загружается при открытии и сохраняется при закрытии. При повторе ролика и
    перемотке память возвращается к состоянию на момент открытия: повторный просмотр идёт так же, как
    первый, крестики не копятся. Цели, которые были захвачены, и всё, что видно, пока камера
    поворачивается, в память не попадают (камера, ведущая дрон, держит его на одном месте кадра).
    «Маска из файла»: маска неба лежит рядом с видео (`<видео>.mask.bin`) и закрывает лес с первого
    кадра; пока идут кадры обучения, она сверяется с видимым и при расхождении учится заново.
    «Два кандидата в тайле», «Фон по ячейкам у кромки леса» (дальние дроны низко над лесом),
    «Полоса у горизонта» (небо выше — раз в N кадров), «Накопление слабых целей» (опыт) — см.
    native/README.md, «Неподвижная камера над горизонтом». «Трекер в секундах»: параметры трекера
    пересчитываются под частоту новых кадров (повторы записи экрана не в счёт).
    «Зоны кадра» (авто — вместе с учётом движения камеры): небо, земля и кромки неба у земли; на кромках
    цель выдаётся, только когда полетела. Видны на кадре с галочкой «маска неба и зоны».
    «Экономия»: весь кадр и крупные масштабы просматриваются раз в N кадров, между ними — только вокруг
    найденных целей.
- **Внизу — шкала видео.** Щелчок или перетаскивание — перемотка в любое место файла (назад тоже):
  чтение продолжается оттуда, треки начинаются заново. На паузе уже обработанный кадр показывается из
  истории сразу, с той разметкой, что была. На шкале отмечено, где алгоритм видел цели: розовый — захват,
  красный — дрон, синий — птица, жёлтый — цель без класса, серый — кадр обработан, целей нет. Если есть
  разметка, нижняя полоса: зелёный — дрон по разметке найден, красный — пропущен. Наведите мышь — номер
  кадра и время. Клавиши: **Shift + ← / →** — на секунду назад / вперёд, **Home** — в начало.
- **В центре — видео.** Колёсико — масштаб, перетаскивание — сдвиг, двойной щелчок — вписать.
  Красный — дрон, синий — птица, жёлтый — цель, класс пока не ясен, серый — статичная помеха,
  светло-серые точки — шум (одиночные отклики без трека), зелёный — разметка.
  Розовый прицел «ЗАХВАТ» — захваченная цель, «ЗАХВАЧЕН ДРОН» — она прошла проверку (жёсткий захват). Линия от цели (у захвата и устоявшихся треков) — куда она
  придёт за 10 кадров при нынешней скорости. Пунктирная рамка — цель на этом кадре не найдена, трек идёт
  по прогнозу; у захвата круг — где она может быть. Наведите мышь на цель — подробности (скорость, ошибка прогноза, вес для захвата).
- **Справа — метрики.** К/с обработки, время детектора и предел к/с, таблица времени по стадиям
  (среднее, p50, p95, максимум), график по кадрам с линией бюджета кадра, пропущенные кадры, загрузка CPU
  и память процесса, число целей по классам, захват и доля кадров с захватом, сдвиг камеры, качество по
  разметке, крупные вырезки целей (захваченная — первая).
  «CSV по кадрам» и «Отчёт JSON» сохраняют замер в файлы. «Вырезки целей» сохраняет цели из последних
  600 обработанных кадров картинками 48x48 (BMP) в папку `<видео>_вырезки` и таблицу `crops.csv` с
  признаками трека, классом от алгоритма и правдой по разметке — набор для настройки классификатора
  дрон/птица и обучения нейросети.

## Мультитест: подбор настроек на папке видео

Кнопка «Мультитест: подобрать настройки на папке видео...» под «Открыть видео» открывает окно поверх
видео. Выберите папку с роликами, отметьте, какие настройки перебирать (через запятую — значения, дробные
через точку), и нажмите «Запустить мультитест». База — текущие настройки приложения (устройство, профиль,
галочки); режим «По одной» меняет каждую настройку отдельно, «Все сочетания» — перебирает сочетания
(не больше 256). Каждое видео прогоняется с каждым вариантом целиком (или первые N кадров), без пропусков
кадров и без имитации устройства, если не отмечено обратное; память помех между прогонами не переносится,
маска неба учится в каждом прогоне заново.

Отчёт складывается в папку `multitest-ГГГГММДД-ЧЧММСС` рядом с видео и обновляется после каждого прогона
(остановка не теряет сделанное):

- `report.html` — вывод (лучший вариант и что даёт каждая настройка), сводка по вариантам и таблицы по
  каждому видео с разницей от базы (зелёный — лучше, красный — хуже), пояснения к столбцам;
- `results.json` — всё то же машиночитаемо: его и присылать на разбор;
- `results.csv` — строка на прогон, открывается в Excel.

Без разметки видны число целей, доля кадров с захватом, смены захвата и скорость. С `<видео>.gt.json`
(вкладка «Разметка») добавляются «дрон найден», «захват на дроне», «жёсткий на дроне», «ложный захват»,
ложные цели, время до обнаружения и до захвата и общая оценка 0..100 (на ролике «нет дронов» — по доле
кадров без захвата). «Небо в поиске» — доля кадра, не закрытая маской неба: если вариант даёт меньше
целей, но и неба в поиске меньше, он не чище, а просто меньше смотрит. Кнопка «взять» в итогах ставит
настройки варианта в приложение.

Без окна (и в CI):

```bat
start /wait Dronolok.exe --multitest D:\видео --vary auto_thr --vary thr=8,10,14 --vary lock_slow --frames 600
```

`--vary ключ[=значения]` — что перебирать (без значений — значения по умолчанию, `--list` — все ключи),
`--set ключ=значение` — изменить базу, `--profile 0..3` — профиль базы, `--mode one|grid`, `--frames N`,
`--warmup N` (первые кадры не входят в точность, по умолч. 25), `--radius пикс.` (цель найдена, если
ближе, по умолч. 12), `--parallel N` (прогонов одновременно), `--realtime` (кадры в темпе видео, с
пропусками), `--emulate` (с замедлением устройства), `--mask-file`, `--out папка`.

## Замер без окна

```bat
start /wait Dronolok.exe --bench video.mp4 --preload 100 --frames 300 --threads 4 --isa sse2 --json report.json --csv frames.csv
```

Параметры: `--camera` кадры в темпе видео с выбросом лишних (как камера; без ключа — максимально
быстро), `--slowdown K` имитация устройства в K раз медленнее, `--governor` авто-упрощение, `--profile 0..3`
профиль (полный, сбалансированный, экономный, минимальный), `--frames N` сколько кадров обработать, `--preload N` загрузить N кадров в память заранее,
`--threads N`, `--isa auto|scalar|sse2|avx2`, `--size WxH` разрешение обработки, `--learn-mask N`,
`--scales 0..4` (0 — авто), `--motion 0|1` (без ключа — авто), `--focus`, `--static N` (память помех,
кадров; 0 — выкл.), `--full-every N`, `--coarse-every N`, `--zones 0|1`, `--json`, `--csv`,
`--tracks треки.csv` (по строке на каждую цель каждого кадра: позиция, класс, захват и его состояние —
для сверки с разметкой), `--dedup` (пропускать повторы кадра), `--no-anchor` (без проверки «на мачте»), `--no-size` (без ожидания размера), `--follow` (камера ведёт цель, виртуальная поворотка;
`--follow-frac 0.5` поле зрения, `--follow-gain 0.3` резкость, `--follow-any` поворачиваться и за
непроверенной целью). В журнале треков есть габарит силуэта захвата и ожидаемый размер
(`bw,bh,size_exp`) и смещение окна поворотки (`view_x,view_y`; координаты целей — исходного кадра). Память помех
в замере не читается из файла и не пишется в него (зацикленный ролик повторяет те же позиции целей, и
накопленная прошлыми запусками память искажала бы результат), `--static-file` — читать и писать. Для
замеров только ядра есть `dronolok_bench.exe` (см. `native/README.md`).

Стресс-проверка (её же гоняет CI): `Dronolok.exe --stress video.mp4 --seconds 30 [--seed N]` — много раз в
секунду случайно меняет настройки, ставит паузу, листает историю, перематывает и открывает видео заново.
Если приложение где-то падает, этот режим обычно воспроизводит падение.

## Сборка

Готовый `Dronolok-win64` собирает GitHub Actions (`.github/workflows/build.yml`): FFmpeg и SDL2
линкуются статически, компилятор MinGW-w64.

Linux (для разработки):

```sh
sudo apt install cmake ninja-build libsdl2-dev libavformat-dev libavcodec-dev libswscale-dev
cmake -S app -B build-app -G Ninja && cmake --build build-app
./build-app/dronolok_app video.mp4
```
